# Custom Base64 Display Encoding — SPEC + PLAN

## SPEC

### Overview

Foretias JSON output currently serializes binary fields (`Vec<u8>`, `[u8; N]`) as JSON integer arrays:

```json
"tbid": [128, 52, 2, 40, 26, 86, ...]
```

This spec introduces a **custom base64 encoding** using alphabet `[a-zA-Z0-9|_]` for **display-only** purposes. Internal wire format, storage, and serde serialization remain **unchanged**.

### Character Set (Verified)

```rust
const BASE64_CUSTOM: [char; 64] = [
    'x', 'I', 'T', 'h', 'b', 't', 'm', 'P', 'o', 'y',
    'q', 'Q', 'B', 'R', 'n', 'C', 'F', 'Y', 'j', 'd',
    'J', '_', 'N', 'i', 'l', 'X', 'O', 'L', 'g', 'c',
    'W', 'E', '|', 'u', '4', '0', 'f', 'e', 'H', 'r',
    's', 'w', 'G', 'S', 'z', 'v', 'A', 'k', '1', 'U',
    'p', 'M', 'D', 'K', 'V', 'Z', 'a', '9', '2', '7',
    '3', '8', '5', '6'
];
```

- 64 unique characters, no duplicates
- Exact permutation of `[a-zA-Z0-9|_]` (26 upper + 26 lower + 10 digits + `_` + `|`)
- No padding character — length implicitly indicates padding

### Encoding Algorithm

Standard base64 grouping (3 bytes → 4 chars) using `BASE64_CUSTOM` lookup. No `=` padding; encoded length implies original byte count: `len % 4 == 0` → `bytes % 3 == 0`, `len % 4 == 2` → `bytes % 3 == 1`, `len % 4 == 3` → `bytes % 3 == 2`.

Decode uses an inverse ASCII-indexed lookup table `INVERSE_BASE64[128]`.

### Architecture Layers

1. **C11 Core** (`p2p/core/src/encoding_custom_base64.c`, `p2p/core/include/foretias_core.h`)
   - `foretias_custom_base64_encode()` / `foretias_custom_base64_decode()`
   - `foretias_custom_base64_encoded_len()` / `foretias_custom_base64_decoded_len()`
   - Defensive: NULL checks, buffer-size checks, character validation, invalid-length rejection (`len % 4 == 1`)

2. **Rust Wrapper** (`p2p/core-engine/src/core/encoding.rs`)
   - `custom_base64_encode(&[u8]) -> String`
   - `custom_base64_decode(&str) -> Result<Vec<u8>, CryptoError>`
   - FFI via bindgen

3. **Display Formatter** (`p2p/core-engine/src/foretias/display.rs`)
   - `format_json_for_display(&serde_json::Value) -> String`
   - Recursively walks JSON, replaces integer arrays (all `Value::Number` in `[0,255]`) with custom-base64 strings, returns pretty-printed JSON

4. **CLI Integration**
   - Rust CLI (`main.rs`): Replace `serde_json::to_string_pretty` with `format_json_for_display`
   - Python CLI (`cli.py`): Python helper `format_binary_fields(obj)` before `json.dumps`
   - PyO3: Add `to_json_display()` method

### What Does NOT Change

- Internal Serde `Serialize`/`Deserialize` on all domain types
- Wire protocol (JSON-RPC, TCP+Noise, HTTP)
- Storage (calendar persistence, encrypted JSONL)
- PyO3 `to_json()` / `from_json()` for cross-language interop
