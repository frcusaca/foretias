# fortias_p2p

**Rust P2P Node** for [Fortias](..) — a cryptographic timestamping and verification system.

Provides the server runtime, CLI client, protocol types, and language bindings (Python) for the TimeFamilyServer.

## Quick Start

```bash
# Debug build (fast, for development)
cd p2p/node && cargo build

# Release build (optimized, LTO, stripped)
cargo build --release

# The binary is at target/release/fortias
```

| Dependency | Debian/Ubuntu | Fedora | Purpose |
|---|---|---|---|
| **libsodium** | `libsodium-dev` | `libsodium` | Crypto backend |
| **libclang** | `clang-dev` | `libclang-devel` | `bindgen` FFI generation |

## CLI Usage

### Start the Server

```bash
fortias serve --addr 127.0.0.1:4001 --chronon-ns 60000000000
```

The server reads optional configuration from `~/.config/fortias/fortias.settings.json`:

```json
{
  "listen_addr": "0.0.0.0:4001",
  "chronon_ns": 60000000000
}
```

CLI flags override config values when explicitly set.

### Stamp a Message

```bash
# Inline message
fortias stamp --message "hello" --server 127.0.0.1:4001

# From file
fortias stamp --message-file ./document.txt --server 127.0.0.1:4001

# Write output to file
fortias stamp --message "hello" -o stamp.json --server 127.0.0.1:4001
```

### Verify (Server-Side)

```bash
fortias verify --message "hello" --fortis <fortis_json> --server 127.0.0.1:4001

# Or read Fortis from file
fortias verify --message "hello" --fortis-file stamp.json --server 127.0.0.1:4001
```

### Prove Verification (Local)

Fetches the calendar from the server and verifies locally — no server-side `/verify` call:

```bash
fortias prove-verification --message "hello" --fortis <fortis_json> --server 127.0.0.1:4001
```

## Architecture

```
fortias_p2p/
├── build.rs              # Compiles C11 core via cc crate, generates FFI via bindgen
├── src/
│   ├── main.rs           # CLI entry point (clap derive, tokio runtime)
│   ├── lib.rs            # Library root
│   ├── core/             # C11 core bindings (fortias_core.h → bindgen)
│   ├── fortias/          # Protocol layer (TickRecord, Fortis, Calendar)
│   ├── server/           # TimeFamilyServer & JSON-RPC handlers
│   └── api/
│       └── python.rs     # PyO3 Python bindings
├── tests/                # Integration tests
└── Cargo.toml
```

| Layer | Location | Description |
|---|---|---|
| **C11 Core** | `../core/` | Compiled by `build.rs` via the `cc` crate |
| **FFI Bindings** | `src/core/` | Auto-generated by `bindgen` from `fortias_core.h` |
| **Protocol** | `src/fortias/` | TickRecord, Fortis, Calendar types |
| **Server** | `src/server/` | TimeFamilyServer, JSON-RPC handlers |
| **CLI** | `src/main.rs` | Clap-derive commands, tokio runtime |
| **Python** | `src/api/python.rs` | PyO3 bindings |

## Cargo Profiles

### dev

Optimized for fast compilation during development:

- 256 codegen units (vs. default 16)
- No optimization on the crate itself (`opt-level = 0`)
- Full optimization on dependencies (`opt-level = 3`)
- No debug symbols

### release

Production-optimized:

- `opt-level = 3`
- Link-time optimization (LTO)
- Stripped binary

## Debugging

```bash
# Stack traces on panic
RUST_BACKTRACE=1 cargo run -- serve

# Verbose logging (uses tracing)
RUST_LOG=debug cargo run -- serve

# Run tests
cargo test
```
