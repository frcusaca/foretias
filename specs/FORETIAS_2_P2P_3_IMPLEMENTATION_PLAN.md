## WHAT v0.3 DELIVERS (and doesn't)

**What a user sees:**
- Two new CLI flags: `--p2p-listen` and `--p2p-dial`
- New log lines showing libp2p connections, identify info, ping RTT
- **That's it.** No application traffic moves over libp2p.

**What the codebase gets:**
- `Communerd` gains a `SwarmHandle` — persistent libp2p swarm running alongside JSON-RPC
- `PeerAddr` gains `peer_id: Option<libp2p::PeerId>` field
- **Zero C11 changes** — libp2p generates its own Ed25519 keypair
- Noise XX encryption on all libp2p connections
- TBID proof handshake over the encrypted stream (application-layer identity binding)
- Automatic reconnection, idle timeout, peer identification

**Why this matters:** v0.4 (DHT discovery) **requires** libp2p PeerId, swarm, and noise. Without v0.3, v0.4 cannot exist.

## TWO-LAYER IDENTITY MODEL

Foretias has **two independent identities**:

| Layer | Identity | Generated By | Managed By | Purpose |
|---|---|---|---|---|
| **Transport** | `libp2p::PeerId` (Ed25519) | `libp2p::identity::Keypair::generate()` | libp2p crate | DHT, Noise handshake, routing |
| **Application** | `TBID` (16-byte + Ed25519 public key) | C11 enclave (`generate_keypair`) | C11 enclave | Calendar identity, stamping, attestation |

**These are NOT derived from each other.** The transport keypair is ephemeral to libp2p and has no relationship to the Foretias TBID. The TBID is the user-visible identity.

### Why Two Layers?

1. **libp2p requires its own keypair** — The Noise handshake and DHT are designed around libp2p's identity types. There's no benefit to forcing libp2p to use our TBID key.

2. **C11 enclave stays intact** — By never asking C11 to export raw key bytes, we preserve the `PrivKeyHandle` abstraction. Future TEE/HSM replacement requires zero Rust changes.

3. **Clean separation of concerns** — Transport identity = "who am I talking to right now?" Application identity = "which time family is this?"

4. **Enclave compatibility** — All P2P operations (DHT, voting, FROST, TBID proofs) work with sign/verify-only crypto. Raw keys never need to leave C11 memory.

### TBID Proof Handshake

After the Noise handshake establishes encryption, each side proves its Foretias TBID by signing a challenge:

```
Alice                                    Bob
  |                                         |
  |--- libp2p dial + Noise XX handshake --->|
  |   (establishes encrypted stream)        |
  |                                         |
  |--- TBIDProofRequest {                   |
  |     nonce: [u8; 32]                    |
  |}                                        |
  |                                         |
  |                --- C11 .sign() --->     |
  |                                         |
  |<-- TBIDProofResponse {                  |
  |     tbid: [u8; 16]                     |
  |     public_key: [u8; 32]               |
  |     signed_payload: {                   |
  |       tbid,                             |
  |       peer_id (libp2p),                 |
  |       nonce,                            |
  |       timestamp                         |
  |     }                                   |
  |     signature: [u8; 64]                |
  |}                                        |
  |                                         |
  |         --- C11 .verify_ed25519() --->  |
  |                                         |
  |<-- TBIDProofSuccess / TBIDProofFailed -->|
  |                                         |
```

**Key design decisions:**
- **Persistent node key for signing**: The TBID proof uses the node's persistent Ed25519 keypair (same one used for stamping). NOT per-tick ephemeral. The TBID itself is the persistent identity.
- **Automatic on connect**: The TBID handshake happens immediately after Noise handshake. No explicit user request needed.
- **C11 operations only**: `sign()` and `verify_ed25519()` are already available. No new C11 functions needed.
- **Nonce prevents replay**: Each TBID proof uses a fresh 32-byte nonce generated by the requester.

## NO C11 CHANGES REQUIRED

This is the critical difference from the original plan. **Zero C11 modifications are needed for v0.3.**

The C11 library already provides everything:
- `sign(msg) → sig` — for creating TBID proofs
- `verify_ed25519(pubkey, msg, sig) → bool` — for verifying TBID proofs

The two-layer identity model means libp2p never touches C11 keys.

**TBID Handshake Types:**

```rust
// p2p/foretias-node/src/communerd/p2p/tbid_handshake.rs
use foretias_core::foretias::types::{Tbid, PublicKey};
use libp2p::PeerId;

/// Request sent to prove identity after connection establishment.
#[derive(Debug, Clone)]
pub struct TbidProofRequest {
    /// Fresh 32-byte nonce to prevent replay attacks.
    pub nonce: [u8; 32],
}

/// Response containing the TBID proof.
#[derive(Debug, Clone)]
pub struct TbidProofResponse {
    /// The 16-byte TBID being proven.
    pub tbid: Tbid,
    /// The Ed25519 public key (32 bytes) used for verification.
    pub public_key: PublicKey,
    /// The signed payload containing: tbid + peer_id + nonce + timestamp.
    pub signed_payload: Vec<u8>,
    /// Ed25519 signature (64 bytes) over the signed payload.
    pub signature: [u8; 64],
}

/// Result of TBID proof verification.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum TbidProofResult {
    /// TBID proof verified successfully.
    Success {
        /// The verified TBID.
        tbid: Tbid,
        /// The libp2p PeerId of the remote node.
        peer_id: PeerId,
    },
    /// TBID proof failed verification.
    Failed {
        /// Reason for failure.
        reason: String,
    },
}
```

**TBID Handshake Protocol:**

```rust
use foretias_core::crypto_server::CryptoServer;
use std::sync::Arc;
use rand::Rng;

pub struct TbidHandshake {
    crypto: Arc<dyn CryptoServer>,
    local_tbid: Tbid,
}

impl TbidHandshake {
    pub fn new(
        crypto: Arc<dyn CryptoServer>,
        local_tbid: Tbid,
    ) -> Self {
        Self { crypto, local_tbid }
    }

    /// Generate a TBID proof request (nonce).
    pub fn generate_request(&self) -> TbidProofRequest {
        let mut nonce = [0u8; 32];
        rand::thread_rng().fill(&mut nonce);
        TbidProofRequest { nonce }
    }

    /// Create a TBID proof response using C11 enclave's sign() operation.
    ///
    /// This is called when we receive a TbidProofRequest.
    pub async fn create_proof(
        &self,
        request: &TbidProofRequest,
        peer_id: PeerId,
    ) -> Result<TbidProofResponse, foretias_core::error::NodeError> {
        // Get our TBID and public key from the crypto server
        let tbid = self.local_tbid;
        let public_key = self.crypto.get_public_key()
            .map_err(|e| foretias_core::error::NodeError::Internal(e.to_string()))?;

        // Build the signed payload: tbid + peer_id + nonce + timestamp
        let timestamp = std::time::SystemTime::now()
            .duration_since(std::time::UNIX_EPOCH)
            .unwrap()
            .as_secs();

        let mut signed_payload = Vec::with_capacity(16 + 64 + 32 + 8);
        signed_payload.extend_from_slice(&tbid.0);
        signed_payload.extend_from_slice(&peer_id.to_bytes());
        signed_payload.extend_from_slice(&request.nonce);
        signed_payload.extend_from_slice(&timestamp.to_be_bytes());

        // Sign using C11 enclave's sign() operation
        let signature = self.crypto.sign(&signed_payload)
            .map_err(|e| foretias_core::error::NodeError::Internal(e.to_string()))?;

        Ok(TbidProofResponse {
            tbid,
            public_key,
            signed_payload,
            signature: signature.try_into()
                .map_err(|_| foretias_core::error::NodeError::Internal(
                    "signature has wrong length".to_string()
                ))?,
        })
    }

    /// Verify a TBID proof using C11 enclave's verify_ed25519() operation.
    ///
    /// This is called when we receive a TbidProofResponse.
    pub async fn verify_proof(
        &self,
        response: &TbidProofResponse,
        expected_nonce: &[u8; 32],
        peer_id: PeerId,
    ) -> TbidProofResult {
        // Verify the signature using C11 enclave's verify_ed25519()
        let valid = self.crypto.verify_ed25519(
            &response.public_key,
            &response.signed_payload,
            &response.signature,
        ).unwrap_or(false);

        if !valid {
            return TbidProofResult::Failed {
                reason: "signature verification failed".to_string(),
            };
        }

        // Verify the nonce matches
        let nonce_offset = 16 + 64; // after tbid + peer_id
        let payload_nonce: [u8; 32] = response.signed_payload[nonce_offset..nonce_offset+32]
            .try_into()
            .unwrap();
        if payload_nonce != *expected_nonce {
            return TbidProofResult::Failed {
                reason: "nonce mismatch".to_string(),
            };
        }

        TbidProofResult::Success {
            tbid: response.tbid,
            peer_id,
        }
    }
}
```

**Swarm construction:**

```rust
// p2p/foretias-node/src/communerd/p2p/swarm.rs
use foretias_core::crypto_server::CryptoServer;
use libp2p::{
    SwarmBuilder, PeerId,
    swarm::SwarmEvent,
    tcp, noise, yamux,
    identity::Keypair,
};
use std::sync::Arc;
use std::time::Duration;
use tokio::sync::mpsc;

pub struct SwarmHandle {
    pub local_peer_id: PeerId,
    pub events:        mpsc::UnboundedReceiver<super::events::NetworkEvent>,
    pub task:          tokio::task::JoinHandle<()>,
}

/// Build and spawn a libp2p swarm with the given keypair.
///
/// The keypair is generated by libp2p, NOT derived from Foretias crypto.
pub async fn build_and_spawn_swarm(
    listen: libp2p::Multiaddr,
    dials:  Vec<libp2p::Multiaddr>,
) -> Result<SwarmHandle, foretias_core::error::NodeError> {
    // Generate libp2p's own keypair - independent of Foretias TBID
    let keypair = Keypair::generate_ed25519();
    let local_peer_id = keypair.public().to_peer_id();

    let mut swarm = SwarmBuilder::with_existing_identity(keypair)
        .with_tokio()
        .with_tcp(
            tcp::TokioTcpConfig::default().nodelay(true),
            noise::NoiseConfig::xx,
            yamux::YamuxConfig::default,
        )
        .map_err(|e| foretias_core::error::NodeError::Internal(format!("{e}")))?
        .with_behaviour(|key| super::behaviour::ForetiasBehaviour::new(key))
        .map_err(|e| foretias_core::error::NodeError::Internal(format!("{e}")))?
        .with_swarm_config(|c| c.with_idle_connection_timeout(Duration::from_secs(60)))
        .build();

    swarm.listen_on(listen)
        .map_err(|e| foretias_core::error::NodeError::Internal(format!("{e}")))?;

    for ma in dials {
        let _ = swarm.dial(ma);
    }

    let (tx, rx) = mpsc::unbounded_channel();
    let task = tokio::spawn(async move { swarm_loop(swarm, tx).await });

    Ok(SwarmHandle { local_peer_id, events: rx, task })
}

async fn swarm_loop(
    mut swarm: libp2p::Swarm<super::behaviour::ForetiasBehaviour>,
    tx: mpsc::UnboundedSender<super::events::NetworkEvent>,
) {
    loop {
        match swarm.select_next_some().await {
            SwarmEvent::ConnectionEstablished { peer_id, .. } => {
                let _ = tx.send(super::events::NetworkEvent::Connected { peer_id });
                tracing::info!(peer = %peer_id, "libp2p connection established");
            }
            SwarmEvent::ConnectionClosed { peer_id, .. } => {
                let _ = tx.send(super::events::NetworkEvent::Disconnected { peer_id });
                tracing::info!(peer = %peer_id, "libp2p connection closed");
            }
            SwarmEvent::Behaviour(ForetiasBehaviourEvent::Identify(event)) => {
                match event {
                    identify::Event::Sent { peer_id, .. } => {
                        tracing::debug!(peer = %peer_id, "libp2p identify sent");
                    }
                    identify::Event::Received { peer_id, info, .. } => {
                        let _ = tx.send(super::events::NetworkEvent::Identified { peer_id, info: info.clone() });
                        tracing::info!(peer = %peer_id, agent = %info.agent_version, "libp2p identify received");
                    }
                }
            }
            SwarmEvent::Behaviour(ForetiasBehaviourEvent::Ping(event)) => {
                if let ping::Event::Success { peer_id, rtt, .. } = event {
                    let _ = tx.send(super::events::NetworkEvent::PingSuccess { peer_id, rtt });
                    tracing::debug!(peer = %peer_id, rtt = ?rtt, "libp2p ping");
                }
            }
            _ => {}
        }
    }
}
```

```rust
impl Communerd {
    #[cfg(feature = "libp2p")]
    pub async fn enable_p2p(
        &mut self,
        listen: libp2p::Multiaddr,
        dials:  Vec<libp2p::Multiaddr>,
    ) -> Result<(), foretias_core::error::NodeError> {

            listen,
            dials,
        ).await?;

        tracing::info!(peer = %handle.local_peer_id, "libp2p swarm started");

        self.swarm_handle = Some(handle);
        // p2p_events_rx is populated from handle.events
        Ok(())
    }
}
```

```rust
        .map_err(|e| anyhow::anyhow!("invalid --p2p-listen: {}", e))?;
    let dials: Vec<libp2p::Multiaddr> = config.p2p_dial.iter()
        .map(|s| s.parse().map_err(|e| anyhow::anyhow!("invalid --p2p-dial: {}", e)))
        .collect::<Result<_, _>>()?;

    communerd.enable_p2p(listen_addr, dials).await?;
}
```

## RISK ASSESSMENT

| Risk | Impact | Mitigation |
|------|--------|------------|
| libp2p 0.56 API differs from spec | Medium — build errors | Phase 1 is just dependency + compile; adjust code to actual API |
| Swarm event loop blocks tokio runtime | Medium — liveness impact | `select_next_some()` is non-blocking; spawned as separate task |
| PeerAddr `#[cfg(feature)]` breaks serde | Low — compile error | Use `#[cfg_attr(feature, serde(default))]` |
| TBID proof payload encoding ambiguity | Medium — protocol mismatch | Canonical encoding: big-endian for integers, fixed-size for all fields |
| TBID proof timing (when to initiate) | Low — race condition | Initiate immediately after `ConnectionEstablished` event |
| Noise XX requires Ed25519 keypair | Low — deterministic | libp2p generates Ed25519 by default; no mismatch possible |
| Port conflict (JSON-RPC vs libp2p) | Low — user error | Foretias uses 99xx range (9901 JSON-RPC, 9901 libp2p); clear error message |

**v0.3 uses fixed ports in the 99xx range:**

| Service | Default Port | Transport |
|---|---|---|
| JSON-RPC API | 9901 | TCP |
| libp2p swarm | 9901 | TCP |

The JSON-RPC is a regular HTTP-like service; the libp2p swarm is a Noise-encrypted connection. ## NAT TRAVERSAL STRATEGY — PRE-REQUISITE FOR POST-v0.3

(@human — this section is NOT implemented in v0.3. It is a **design requirement** that must be resolved before v0.4 production deployment. Without NAT traversal, foretias nodes behind home routers cannot connect. This is documented here because the port strategy depends on it.)

**The problem:** Most internet users are behind NAT. A fixed port like 9901 is unreachable unless the router forwards it. We cannot rely on users configuring port forwarding manually.

**Industry patterns (as of 2026):**

| Approach | Used By | Complexity | Reliability |
|---|---|---|---|
| **Default protocol port** | Bitcoin (8333), Ethereum (30303) | Low | Poor — only works if user opens port |
| **UPnP / NAT-PMP** | BitTorrent, older P2P apps | Medium | Moderate — blocked by some ISPs |
| **Hole punching** | WebRTC, Tailscale, Syncthing | High | Good — requires coordination server |
| **Relay fallback** | Tor, Signal | High | Best — works everywhere, adds latency |
| **Randomized port + STUN** | WebRTC, modern P2P | Medium | Good for UDP, poor for TCP |

**What libp2p provides (v0.56):**
- `libp2p-autonat` — determines if the local node is behind NAT (behaves as server or client)
- `libp2p-relay` — circuit v2 relay for nodes that cannot accept direct connections
- `libp2p-quic` — QUIC transport (UDP-based, better NAT traversal than TCP)

**Foretias requirement (pre-v0.4):**
1. **AutoNAT** — every node determines its reachability on startup. If unreachable, it logs a warning and attempts relay.
2. **Relay fallback** — if direct TCP fails, try libp2p relay. If relay unavailable, fall back to requiring manual `--p2p-dial` with the peer's public address.
3. **QUIC transport** — add `quic` feature alongside TCP for better NAT traversal on UDP.
4. **Port strategy evolution** — after hole-punching works, move from fixed 99xx to randomized ephemeral ports, discovered via DHT.

**Deferred to v0.5 hardening** — v0.3 and v0.4 demo on localhost/LAN where NAT is not an issue. NAT traversal is a **v0.5 MUST** for production deployment.

## COMPATIBILITY NOTES

- v0.3 is **backward compatible** with v0.2 calendars — no schema changes
- v0.3 is **backward compatible** with v0.2 JSON-RPC — no protocol changes
- libp2p is **opt-in** — if `--p2p-listen` is absent, zero libp2p code runs
- libp2p feature is **cfg-gated** — `foretias-node` compiles without libp2p if the feature is disabled
- **Zero C11 changes** — no modifications to the C11 library
- **Zero PrivKeyHandle changes** — raw bytes never leave C memory (design preserved)
- **Two-layer identity model** — transport identity (PeerId) ≠ application identity (TBID)
- **TBID proof is application-layer** — happens after Noise handshake, uses C11 sign/verify only
