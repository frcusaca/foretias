# Custom Base64 Display Encoding Specification

## Overview

Foretias JSON output currently serializes binary fields (`Vec<u8>`, `[u8; N]`) as JSON integer arrays:

```json
"tbid": [128, 52, 2, 40, 26, 86, ...]
```

This is verbose and not copy/paste friendly. This spec introduces a custom base64 encoding using the alphabet `[a-zA-Z0-9|_]` for **display-only** purposes. Internal wire format, storage, and serde serialization remain **unchanged** (integer arrays).

## Custom Alphabet

```rust
const BASE64_CUSTOM: [char; 64] = [
    'x', 'I', 'T', 'h', 'b', 't', 'm', 'P', 'o', 'y',
    'q', 'Q', 'B', 'R', 'n', 'C', 'F', 'Y', 'j', 'd',
    'J', '_', 'N', 'i', 'l', 'X', 'O', 'L', 'g', 'c',
    'W', 'E', '|', 'u', '4', '0', 'f', 'e', 'H', 'r',
    's', 'w', 'G', 'S', 'z', 'v', 'A', 'k', '1', 'U',
    'p', 'M', 'D', 'K', 'V', 'Z', 'a', '9', '2', '7',
    '3', '8', '5', '6'
];
```

Verified: 64 unique characters, exact permutation of `[a-zA-Z0-9|_]`. No padding character — the encoded string's length implicitly indicates padding:
- `len % 4 == 0` → original bytes `% 3 == 0`
- `len % 4 == 2` → original bytes `% 3 == 1`
- `len % 4 == 3` → original bytes `% 3 == 2`

## Encoding Algorithm

Standard base64: group bytes into 24-bit blocks (3 bytes → 4 chars), encode each 6-bit index into `BASE64_CUSTOM`. No `=` padding appended.

## C11 API

New header: `p2p/core/include/foretias_custom_base64.h` (included from `foretias_core.h`)

| Function | Purpose |
|---|---|
| `foretias_custom_base64_encode(input, len, output, output_len)` | Encode bytes to custom base64 string |
| `foretias_custom_base64_decode(input, len, output, output_len)` | Decode custom base64 string to bytes |
| `foretias_custom_base64_encoded_len(input_len)` | Compute output buffer size |
| `foretias_custom_base64_decoded_len(input_len)` | Compute decoded buffer size |

All functions return `FORETIAS_OK` or `FORETIAS_ERR_BAD_INPUT`. Defensive boundary checks: NULL pointers, invalid characters, invalid lengths (`len % 4 == 1`).

## Rust Wrapper

New module: `p2p/core-engine/src/core/encoding.rs`

| Function | Purpose |
|---|---|
| `custom_base64_encode(&[u8]) -> String` | Encode via C11 FFI |
| `custom_base64_decode(&str) -> Result<Vec<u8>, CryptoError>` | Decode via C11 FFI |

FFI bindings generated by bindgen from the C11 header.

## Display Formatter

New module: `p2p/core-engine/src/foretias/display.rs`

`format_json_for_display(&serde_json::Value) -> String` — recursively walks the JSON value tree, replaces any array where all elements are integers in `[0, 255]` with a custom-base64 string, then returns `serde_json::to_string_pretty` of the result.

This is a **post-processing** function only. It does NOT modify Serde derives, wire protocol, or storage.

## Integration Points

| Output path | How |
|---|---|
| Rust CLI (`main.rs`) | Replace `serde_json::to_string_pretty(&result)` with `format_json_for_display(&result)` in `cmd_stamp`, `cmd_verify`, `cmd_prove_verification` |
| Python CLI (`cli.py`) | Add `format_binary_fields(obj)` helper before `json.dumps` |
| PyO3 bindings | Add `to_json_display()` method alongside existing `to_json()` |

## What Does NOT Change

- Internal Serde `Serialize` / `Deserialize` on all domain types
- Wire protocol (JSON-RPC, TCP+Noise, HTTP)
- Storage (calendar persistence, encrypted JSONL)
- PyO3 `to_json()` / `from_json()` for cross-language interop
